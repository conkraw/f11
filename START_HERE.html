PICU SMARTPHRASE / VERSION 2

Medications and a landscape handoff

This updates your working web app. It does not require another Python installation or the older local OCR packages.

Keep your existing Streamlit Secrets, including the password hash and encryption key. Keep the current private data repository. Do not generate new secrets for this update.

Update the existing app

  1. Save your open handoffs. Extract this ZIP.
  2. Upload the contents of this folder to the existing application code repository. Replace matching files and add medications.py. Include the updated requirements.txt, which adds ReportLab for PDF export.
  3. Keep app.py as the entry point and keep your current deployment Secrets unchanged. Never upload .streamlit/secrets.toml or clinical records.
  4. Restart/reboot the deployment after dependencies install. Sign in and select Load synthetic example for the first test.

The existing encrypted archive is read with the same key and path. Its contents are upgraded in memory. Your next explicit save writes the new schema with medication records and mapping rules. This does not create a new data repository or clear old handoffs. Avoid rolling back only some application files after saving the new schema.

Use the medication import

  1. Open a room and paste the complete SmartPhrase or its paired A/B blocks. Copy directly from Epic so tabs between table columns are preserved.
  2. Click Read Diagnoses + Medications. Review and apply diagnoses in the first tab. Open Medications to review the detected orders.
  3. Each line shows its complete handoff wording and destination. Expand an order to correct the name, dose, route, frequency, recorded rate, destination, or custom wording. Check the review box, then click Apply medications to handoff.
  4. In Admin, select a detected medication, choose its system, confirm the rule contains no patient information, and save it. The optional checked setting reapplies all saved mappings to the current room's draft and import preview. This resets per-order destination overrides in that room. It does not save the clinical handoff.
  5. Review the landscape preview and save the handoff to encrypted GitHub. Download the landscape PDF for printing.

What is recognized

SourceResult
Bullet followed by medication table columnsOne separate order with medication/formulation, Dose, Route, and Frequency.
Provider and Last AdminNot retained in the parsed medication record or included in the generated handoff.
Continuous fluid with blank Dose and a Last RateComplete fluid description followed by @ rate. No dose is inferred. The timestamp remains available in the editor.
Medication without a saved system ruleOther Medications.
Scheduled and PRN orders for the same medicationSeparate entries. No order is silently merged or discarded.
Different product-label amount and ordered doseThe formulation remains visible and the actual Dose column is explicitly labeled. No dose is recalculated.

A Last Rate of zero does not mean the app has determined that an order was discontinued. Rates are source records, not a live pump feed. Confirm them against Epic.

Save your own rules

For example, save acetaminophen to Neurologic and sodium acetate to FEN / GI. The starting mapping dictionary is empty, so you remain in control. Match by medication name, not by a patient's dose.

Matching ignores capitalization and uses complete name prefixes, not fuzzy drug-name guesses. A more specific prefix takes priority. heparin flush can therefore have a different destination from heparin. An exact complete-name rule has the highest priority.

Changing mappings does not silently rewrite every saved room. It updates the current draft if you select that option, or applies on the next import. Save the reviewed handoff explicitly.

Landscape output

The handoff has eight top columns: PATIENT, NEURO, RESP, CARDIAC, FEN / GI, HEME, ID, and LABS. Other Medications spans the width below them. Lower rows provide laboratory trends, goals/follow-up, airway, last intubation, access, and drains/tubes. Longer entries continue onto additional landscape pages rather than being cut off.

Open the synthetic PDF layout example or open its printable HTML version.

Only Diagnoses and Medications are automatically imported at this stage. The remaining clinical sections and the lab trend area are editable manually. No lab fishbone values or ventilation settings are invented from the sample.

Existing notes and reimports

System notes and medication records are kept separately. Replacing an imported medication list does not erase your notes. Reimporting requires a confirmation rather than accumulating repeated copies. The per-order destination dropdown affects that order only. Admin rules affect future matching entries.

Privacy and deployment limits

Use synthetic information until your institution approves both hosting and storage. The host receives pasted text before encryption. A private repository, shared app password, and encryption alone do not establish clinical approval or HIPAA compliance.

Clinical handoff fields, structured medication entries, room data, and mapping rules are encrypted before a GitHub save. The original pasted SmartPhrase is not saved into the archive. It may remain in browser/server session memory until cleared. Exported PDFs/HTML/text are unencrypted. Git history retains earlier encrypted versions.

No patient-name or MRN field was added. Other clinical details and room assignments can still identify a patient. Always confirm the current patient in Epic, especially after a room changes occupants.

First-time deployment only

For a new app, initialize a private code repository and a separate private data repository. Use the included create_secrets.py or Generate_Secrets.ipynb helper to create a password hash and an independent encryption key. Keep the key in an approved password manager. Give a fine-grained GitHub token Contents read/write access only to the data repository.

Set app.py as the Streamlit entry point, add the generated configuration to deployment Secrets, and start with clinical_use_approved = false. There is one app sign-in password. Admin does not have a second password. These helpers are not needed to update your current working deployment.
