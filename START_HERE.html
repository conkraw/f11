PICU HANDOFF / VERSION 6.22

A guide for your team, with separate Admin access

Read the user guide or open the full Admin setup instructions.

Update the application

Save your open work. Extract PICU622.zip and open PICU_Handoff_v6_22_User_Guide. Upload its contents to the existing code repository, replacing matching files. Keep app.py at the root.

Keep your app password, encryption key, GitHub token and all other existing Secrets. Do not run the original secrets generator. This update adds only one Admin password-hash setting.

Add your second password

Open Generate_Admin_Password.ipynb in local JupyterLab and run its cell, or run python set_admin_password.py locally. Choose a different password of at least 12 characters. Copy the single generated admin_password_hash line into the existing [app] section of your deployment Secrets. Save and restart as needed. The helper does not write files or create a new encryption key.

Publish your SmartPhrase

Sign in normally, open Admin, and unlock with the second password. Fill in the SmartPhrase name, reusable source definition and optional local Epic notes. The learner guide is already filled in and is editable. Click Save instructions and SmartPhrase.

The actual Epic name and definition have not been supplied, so those fields begin blank. Use the source with your institution's SmartLinks, not expanded patient results. Publishing in this app does not install anything inside Epic.

Help users find it

Users open Instructions / SmartPhrase in the sidebar or expand Instructions and Epic SmartPhrase at the top of Handoff. They can copy the source and download the guide with only their usual app login. Admin is required only for editing Admin settings and publishing teaching content.

Preserved behavior

Clinical parsing, room autosave, the latest-gas and CBC rules, save times, lab placement, medication groups, and printed handoffs are unchanged. No new dependencies or clinical archive schema changes are required. The guide is encrypted separately in the existing private data repository.

Before using it

Check the workflow with synthetic information. Verify that a normal user can read the guide but cannot open Admin, that a wrong Admin password is rejected, and that the published guide remains after signing in again. See TEST_REPORT.md for the checks run here and their limitations.
